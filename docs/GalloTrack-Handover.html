GalloTrack UI/UX migration — handover

Everything a new owner needs: what changed, how it is enforced, where the sharp edges are, and what is still open. Written for Hazel, but self-contained enough to be read cold.

Are we done? Almost — and here is the precise shape of "almost"

The engineering work is complete. All eight S2 findings are fixed and gated; six of nine S3 are fixed, three are deliberately partial; one S4 is open by decision. Type scale, contrast, labels, dialogs, toasts and mobile layout all measure zero. Nothing is held together by discipline — each fix has a gate that fails if it regresses.

What is not done is the human half of the audit. The workbench requires the app to be walked in both themes, driven by keyboard, listened to with a screen reader, and zoomed. Six of those seven passes are still blank, and a blank check is not a pass — so the formal verdict still reads Incomplete under its own rule 2. It cannot read Approve until someone does them, and the honest expected landing point is Approve with fixes, because three S3 items are partial by design.

02 · What shipped

Seven phases, each independently revertible

The migration was planned as seven pull requests so that any phase could be backed out alone. All are merged. The order matters: each phase assumed the one before it, which is why foundations landed before components and components before remediation.

03 · Enforcement

Seven gates, and why they ratchet

The gates exist because a standard that is not enforced decays within a sprint. Four are static scans, two are accessibility tooling, one drives a real browser.

The important design choice is that the static scans ratchet rather than block. Each records the current violation count per file in a committed baseline and fails only when a file gets worse. That let the gates land mid-migration instead of waiting on a backlog, and it means the baseline can only ever shrink. Two are already at zero — which is stronger than baselined, because zero means a regression fails immediately rather than being absorbed by an old ceiling.

Why gate 7 exists and what it caught. Static analysis could not do this job. A regex pass produced 146 hits that were nearly all false positives — decorative blur circles that are meant to be clipped, tables inside their own scroller — and it was blind to the failure that mattered, because content clipped by an overflow: hidden ancestor produces no scrollbar and no document overflow to measure. Driving a real browser found a 4px overflow in the OTP inputs on a route my hand-written route list had never included.

04 · Architecture

The pieces you are inheriting

Six things carry the system. Everything else is ordinary page code.

components/ui/

Nineteen primitives — Button, FormField, Input, SearchInput, Modal, Toast, Badge, Card, StatCard, PageHeader, Table, EmptyState, Skeleton, Spinner, Tabs, Pagination, Tooltip, Breadcrumbs, SkipLink. Variants via CVA, named exports, one barrel. Adding a primitive means adding a test beside it — axe runs in the suite.

app/globals.css

The token layer. Every colour role resolves to a dark value in light mode and a light value in dark mode, so a component writes text-success once and gets 7.7:1 or 10.3:1 without a dark: pair. The type scale is two tiers only: 14px body, 12px floor.

lib/chart-tokens.ts

Chart.js draws to a canvas, so it cannot read CSS variables. This samples computed styles instead — and subscribes to the class attribute on <html>, because reading during render can beat next-themes writing the class and paint a light chart with dark values.

lib/toast-bus.ts

A module-level dispatcher. Most toast calls live inside provider components, which cannot call a hook, so the mounted provider registers itself here and non-component code calls toast() directly.

scripts/standard-gates.mjs

The four static scans plus the ratchet. --update re-records the baseline; do that only when you have genuinely removed violations, never to silence a regression.

scripts/mobile-gate.mjs

Discovers routes from app/**/page.tsx, so a new page is covered the moment it exists. No route list to maintain.

05 · Daily use

Commands

# the fast loop — a second or two, no external dependencies npm run gate:static # 4 static scans against the ratchet baseline npm run typecheck # tsc --noEmit npm test # 210 tests # before a commit npm run gate # static + tsc + eslint + tests # needs a running server and a browser npm run dev # in one terminal npm run gate:mobile # 63 layout checks in the other # housekeeping npm run lint:fix npm run format

One thing that will waste your time if nobody tells you. ESLint on this project costs 13–20 seconds before it reads a single file — plugin-graph startup, not per-file work. It is fixed overhead, which is why --cache cannot remove it and why scoping the paths does not help (57s scoped vs 54s full). Use gate:static + typecheck + test while iterating and run gate once per change set. Also: do not run npm run build while next dev is running — both write to .next, and doing it repeatedly corrupted the dev server badly enough that every route 404'd.

06 · Sharp edges

Things that cost time to discover

Each of these was found the hard way during this migration. They are written down so they cost time once.

Tailwind v4 has no --duration-* theme namespace

A custom utility like duration-base silently generates nothing. Only bare numeric values work — duration-150, duration-200, duration-300. The motion tokens in :root are for hand-written CSS only. Verified against compiled output, not assumed.

Tailwind already defines --ease-out and --ease-in-out

Declaring your own in :root does not override them — whichever block lands last wins, and it is not yours. An early attempt set a custom easing that was silently ignored. The fix was to stop overriding and use Tailwind's values.

Unlayered CSS beats Tailwind's utilities

Tailwind wraps utilities in @layer, and unlayered rules win regardless of specificity. That is why one global :focus-visible rule neutralises all 80 outline-none call sites without an !important — and also why adding focus-visible:outline-none to a component does nothing.

backdrop-filter creates a stacking context and a containing block

A dropdown inside a blurred card is trapped: its z-50 cannot escape, and a fixed inset-0 click-catcher positions against the card instead of the viewport. This broke the dashboard date-range picker. The blur was inert anyway — nothing scrolled behind it — so it was removed.

flex-1 will not shrink below a flex item's intrinsic width

Add min-w-0. And w-full plus shrink-0 on the same flex child is contradictory — w-full claims the whole row while shrink-0 refuses to give any back. That single pair caused three separate mobile breaks.

Playwright's Windows host check needs a separate helper

If winldd is missing or half-installed, launch fails with "Executable doesn't exist at ...PrintDeps.exe" even though the browser is fine. The mobile gate falls back to any Chromium already in the standard cache, and honours PLAYWRIGHT_CHROMIUM_PATH.

PowerShell will quietly ruin a bulk edit

Two of them during this migration: $matches is an automatic variable that -match overwrites, and .NET numbers named regex groups after unnamed ones, so Groups[1] was not what it looked like. Both corrupted files and both were caught in the diff before commit. If you script a codebase-wide edit, verify the mechanism on a sample string first.

08 · First week

If you only do five things

  1. Run npm run gate and npm run gate:mobile once so you have seen green yourself, then read /design-kit in the browser — it renders every token and primitive, so it is the fastest way to learn the system.Roughly twenty minutes, and it replaces reading the standard end to end.
  2. Walk the six runtime passes in the post-fix report.This is the only thing standing between the migration and a formal verdict. It is also the fastest way to find anything the automation missed.
  3. Decide L7 — delete the three unused components or wire the splash back up.It is the last open finding and it needs a product opinion, not an engineering one.
  4. Before your first codebase-wide edit, read section 06.Every entry there corrupted files or wasted an hour during this migration.
  5. Do not re-record a gate baseline to make a failure go away.--update is for when you have genuinely removed violations. The baselines are the reason the standard has held.
