GalloTrack UI Standard

The single source of truth for how GalloTrack looks, behaves, and is built. Every phase of the UI/UX upgrade plan cites this document, and every enforcement gate in CI is derived from it. It exists because the current codebase has no shared component layer, no type scale, and no accessibility floor — 54 files re-implementing the same buttons, cards, modals and toasts by hand.

14px / 12pxBody text floor / absolute minimum size. 835 current sizes below it.
4.5:1 · 3:1Text and UI-component contrast minimums, measured not eyeballed.
16Shared primitives in components/ui/ replacing ~40 inline re-implementations.
6CI gates that keep the standard from decaying after the migration.

How to read this: sections 1–4 define the foundations (tokens, type, color) that live in app/globals.css. Section 5 defines the component layer. Sections 6–8 define behaviour — layout, accessibility, motion. Section 9 lists the CI gates. Section 10 is the live migration tracker. Where a rule maps to a WCAG 2.2 success criterion, the criterion is named so it can be verified against the review workbench.

01 · Foundations

Design tokens

Tokens are the contract between the design and the code. A component may only reference a token — never a literal colour, radius, or duration. The current codebase ships 80 hardcoded hex values across .tsx files on top of a 10-key semantic palette, which is why charts, auth screens and cards drift out of sync the moment the theme changes.

The palette below is a strict extension of what already exists in app/globals.css: the ten semantic surface keys stay exactly as they are, and the missing layers — accent, status, radius, shadow, motion, focus — are added so that no component ever needs a raw value again.

Colour roles — surfaces

Unchanged from the current implementation. These are theme-aware and must be used for every surface, border and body of text.

Why the light values are darker than the dark values: contrast is a ratio, not a brightness. #10b981 on white is 2.54:1 — a fail — while #047857 on white is 5.48:1 — a pass. The same hue therefore has to be re-tuned per theme, which is exactly checklist item M6. Tokens make that a one-line change instead of a hunt.

Why --ring is just a colour: the focus rule is one global selector, so it only needs the colour and the width as constants. Both values clear 3:1 against the page background in their own theme by a wide margin — 17.06:1 light, 15.76:1 dark — which is what lets a single rule serve every control instead of 80 hand-tuned replacements. The rule shipped in PR 3 as an unlayered :focus-visible selector, so it outranks Tailwind's @layer utilities outline-none without an !important — that is what neutralises all 80 of those call sites at once. It is keyboard-only by construction, so the app looks identical to a mouse user.

A foreground per fill, not one global text-white: white on the dark-theme --danger (#fb7185) is 2.69:1 — a fail. The dark theme therefore pairs that fill with #4c0519 (5.81:1) instead. This is why the fill and its label are two tokens: a single global white would silently fail in exactly one theme, which is the hardest kind of contrast bug to catch in review.

Status of these values: the status, motion and focus tokens shipped in PR 2; the role accent and the three-size radius scale shipped in PR 4. The radius migration was deliberately deltas of two pixels or fewer — xl 12→10, 2xl 16→16, lg 8→6, md 6→6 — with only the oversized 3xl (24→16) moving materially, which is the correction the audit called for. PR 3 made components/ui/ the first consumer, so from PR 3 onward the palette re-tunes in one file rather than nine hundred.

Why the control border needed its own token: --input could not simply be darkened, because it is doing two jobs — it is the border in the few places that use border-input, and it is the fill in dark mode via dark:bg-input. Raising it to 3:1 would have turned every dark-theme field into a light grey box. --input-border separates the two, measured at 4.26:1 light (on white) and 3.75:1 dark (on the card), both clear of the 3:1 minimum in WCAG 2.2 1.4.11.

On the metadata text fix: text-slate-400 is 2.56:1 on white but 6.96:1 on the dark card — it fails in one theme and passes in the other, which is why it survived review for so long. It already carried dark:text-muted-foreground in 137 of 148 places, so collapsing to the single theme-aware token fixes light mode and leaves dark provably untouched.

These three durations deliberately equal Tailwind's core utilities — duration-150 / duration-200 / duration-300 — so a component may use either the utility or var(--duration-*) and get exactly the same number. (Tailwind v4 has no --duration-* theme namespace, so a custom-named utility like duration-base does not generate; this was verified against the compiled CSS rather than assumed.) Easing is likewise Tailwind's built-in ease-out / ease-in-out tokens at the values shown — deliberately not overridden, because Tailwind already emits --ease-out in :root and a second declaration of the same name is silently shadowed by whichever block lands last.

All transitions resolve through a single @media (prefers-reduced-motion: reduce) block that sets durations to 1ms and disables transform-based animation. See Motion.

02 · Foundations

Typography

This is the largest single defect in the current UI. The app contains 835 arbitrary pixel font sizes across 39 files — 317 at 10px, 280 at 9px, 95 at 8px, plus stray 7px and 6px. In practice text-[10px] is used more often than text-sm. Alongside that, font-black appears 514 times and font-bold 460 times, so almost everything is shouting and nothing has hierarchy.

The scale below is the whole permitted set. A font size that is not on this list does not ship. The floor is a hard rule: 14px body, 12px absolute minimum, because 8–9px text fails 1.4.4 (resize) in practice — users cannot zoom it past the browser's minimum without losing layout — and it fails the readability intent of every readability check in the workbench.

Not allowed

  • Any text-[Npx] below 12 — that is 732 instances today.
  • text-xs (12px) used for body prose.
  • font-black as the default heading weight — reserve 800 for display/h1 only.
  • Uppercase + tracking-wider on more than a label (currently ×129).
  • Two weights on one line doing the same job.

Required

  • One h1 per page, owned by PageHeader — the shell stops emitting its own.
  • Heading levels descend without skipping (1.3.1 / 2.4.6).
  • Body 16/1.65; tables and helper text 14/1.5.
  • Truncation never hides an ID, status, or amount (T9) — show the value on hover/focus.
  • Prose measure capped at 72ch (T7).

The calculator in the review workbench truncates rather than rounds, because 4.49:1 does not meet 4.5:1. Any ratio in this document was truncated the same way. When a value sits on a gradient or a backdrop-blur layer — which the dashboard uses liberally — sample the rendered pixel, not the CSS.

Chart colours

Chart.js options are configured once with hardcoded hex and never re-read on theme change, so they are correct in one theme and wrong in the other. Charts must pull from CSS custom properties via getComputedStyle at mount and on theme mutation, using a two-series-safe palette (a distinct hue per series, each verified at 3:1 against both card surfaces).

// one palette, verified in both themes — never inline hex in a chart config
const readChartTokens = () => {
  const s = getComputedStyle(document.documentElement);
  return {
    series: [s.getPropertyValue('--chart-1'), s.getPropertyValue('--chart-2'),
             s.getPropertyValue('--chart-3'), s.getPropertyValue('--chart-4')],
    tick:   s.getPropertyValue('--muted-foreground'),
    grid:   s.getPropertyValue('--border'),
    surface:s.getPropertyValue('--card'),
  };
};
04 · Component layer

Component inventory

Sixteen primitives in gallotrack-next/components/ui/, built with plain React + clsx + class-variance-authority on top of the tokens above. No new paradigm, no component framework — the point is that a button looks and behaves the same on all 27 pages, and that accessibility is solved once in the primitive instead of 173 times by hand.

Today there is no Button, Card, Badge, Input, Modal, Table, Toast, EmptyState, Skeleton or PageHeader. What exists instead: five separate StatCard implementations, eight modal shells each re-implementing the overlay, two competing toast systems, roughly 31 hand-written "No … found" blocks, 173 unshared buttons across five padding scales and two different primary styles, and 95 labels with zero htmlFor.

Button migrate

One primary style, one danger style, four sizes. Loading state is built in, so double-submit prevention (F12) comes free.

  • Variants: primary · secondary · ghost · danger · link
  • Sizes: sm 36px · md 40px · lg 48px — every size clears the 24×24 CSS px floor of WCAG 2.2 2.5.8 · AA; sm is for dense table rows only
  • Props: loading, iconLeft, iconRight, fullWidth
  • Replaces: 5 paddings (58/50/24/22/5 call sites), 2 primary styles (gradient + solid)

FormField migrate

Label, control, hint and error as one unit with a real htmlFor/id pair. This is the fix for 95 unassociated labels.

  • Props: label, hint, error, required, optional
  • Error renders as text with role="alert" — never colour alone (C8, F4)
  • Wraps: Input · Select · Textarea · Checkbox · Switch
  • Replaces: 81 inputs + 41 selects styled by hand, 5 divergent field recipes

Modal S2 fix

Eight shells today have no role="dialog", no focus trap, no focus return, and the whole app has one Escape handler.

  • Behaviour: role="dialog" + aria-modal + aria-labelledby
  • Focus moves in on open, returns to the trigger on close
  • Esc closes; backdrop click closes; body scroll locked
  • Traps Tab inside the panel

Toast S3 fix

Two systems live at once: a global context and per-page local boxes, none of which announce.

  • Single ui-context provider, rendered once in the shell
  • role="status" + aria-live="polite" — announced without moving focus (F10)
  • Variants: success · error · info · loading; auto-dismiss with pause-on-hover

Badge migrate

Status pills currently use six paddings and 129 hand-typed uppercase/tracking combos.

  • Tone: neutral · success · warning · danger · info · accent
  • Never communicates status by colour alone — icon or text always accompanies (C8)
  • Fixed 12px floor, fixed px-2 py-0.5 + rounded-full

Card · StatCard migrate

Five StatCard implementations today, each with its own accent mapping.

  • Card, CardHeader, CardTitle, CardContent, CardFooter
  • StatCard: label · value · trend · icon, one accent scale
  • radius-md + shadow-1 — the elevation rule

PageHeader S3 fix

26 h1 elements across 15 pages; the shell emits one too, so most pages render two.

  • Owns the single h1, breadcrumb, description and page actions
  • Shell breadcrumb becomes a non-heading element
  • settings and profile (which start at h2) gain their missing h1

Table migrate

9 tables, 65 th, zero caption, zero scope.

  • Built-in caption, scope="col|row", sortable headers as buttons
  • Wrapper scrolls horizontally at 320px — never the page (R2)
  • Sticky header + zebra optional; row density sm/md/lg

EmptyState migrate

~31 "No … found" blocks across 13 files, only one of them a component.

  • Icon · title · description · primary action · secondary link
  • Used by every list, table and grid — one voice for "nothing here"
  • Covers the L5 empty-state requirement

Skeleton / Spinner migrate

Zero skeletons in the app; nine animate-pulse, four ad-hoc spinners, plus raw "Loading…".

  • Skeleton mirrors the real layout so nothing jumps on load (L6)
  • Spinner for inline actions; aria-label + role="status"
  • Both disabled under prefers-reduced-motion → static block

Tabs · Pagination · Tooltip migrate

Tabs are re-typed per page; Pagination exists but only one of three lists uses it.

  • Tabs: roving tabindex, arrow keys, aria-selected
  • Pagination: adopt the existing component everywhere
  • Tooltip: dismissible, hoverable, stays until dismissed (T4)

SearchInput migrate

The pl-9 icon-input recipe is retyped in 8 files.

  • Icon, clear button (with a name), result count slot
  • Debounced via the existing lib/use-debounce.ts
  • Visible label or aria-label — never placeholder-as-label

Breadcrumbs · SkipLink S2 fix

There is no skip link anywhere, so every keyboard pass re-traverses the whole sidebar.

  • SkipLink is the first focusable element in the shell
  • Target is <main id="content">; visible only on focus
  • Landmarks: one banner, one main, one contentinfo
05 · Behaviour

Layout and shell

The shell (app/(dashboard)/layout.tsx) already applies p-4 sm:p-6 md:p-8 to <main>. Six admin pages then apply another p-4 sm:p-6 lg:p-8 wrapper inside it, with three different max-w-* values (3xl, 6xl, 7xl), plus a min-h-screen inside an h-[100dvh] overflow-y-auto container. The result is double horizontal padding, inconsistent content widths between sibling pages, and a page that scrolls inside a page.

Shell owns chromeSidebar, topbar, mobile tab bar, toast host, modal host. Nothing else renders fixed UI.
Main owns paddingOne p-4 sm:p-6 md:p-8. Pages never re-apply horizontal padding.
Page owns widthA single <Page> wrapper sets max-w-6xl (forms/settings max-w-3xl). One value per family.
PageHeader owns h1Title, breadcrumb, description, actions. The shell breadcrumb stops being a heading.
Sections own rhythmspace-y-6 between sections; Card inside; no min-h-screen, no nested background.

Remove

  • The min-h-screen … max-w-7xl wrapper inside main (6 admin pages).
  • Per-page full-bleed backgrounds and blurred blobs painted inside a shell that already painted bg-background.
  • Three competing max-w-* values on sibling pages.
  • Duplicate nav data: OWNER_NAV / OWNER_MOBILE / ADMIN_NAV / ADMIN_MOBILE → one array with a short label.

Adopt

  • One Page component: max-w-6xl mx-auto space-y-6.
  • Role accent decided once — either apply emerald/amber everywhere from the token, or drop the role accent. Today the shell flips it but pages hardcode emerald.
  • Mobile: bottom tab bar stays; add the sidebar as a drawer only if nav grows past 6 items.
  • Safe-area padding on every fixed bar (env(safe-area-inset-bottom) — already correct on the tab bar, extend to toasts).

06 · Behaviour

Accessibility floor

WCAG 2.2 level AA is the bar, and the current codebase is not close: 4 aria-* attributes in 54 files, 0 htmlFor against 95 labels, 0 skip link, 0 aria-live, 0 role="dialog", 26 h1 elements, and 9 icon-only buttons between 16 and 20px — below the 24×24px target floor of 2.5.8.

These are not "nice to haves"; each maps to a success criterion that the workbench scores as a pass or a fail. The rules below are the minimum for anything that ships after this migration.

Verification is part of the rule. Each rule above is checked three ways: eslint-plugin-jsx-a11y in CI (static), vitest-axe on the primitives (automated), and one manual pass per release using the snippets in the review workbench — heading outline, missing alt, unlabeled fields, small-target finder, grayscale check. An automated scan is evidence, never a verdict (A6).

07 · Behaviour

Motion and states

The app ships a family of "antigravity" float animations — infinite loops on cards, badges and avatars — used 30 times across the profile and profiling screens, plus a hover scale(1.014) with a glow. Two of the animation classes actually referenced in the codebase don't exist: animate-fadeIn is used 43 times with no @keyframes fadeIn defined, and animate-in fade-in slide-in-from-right-4 requires tailwindcss-animate, which is not installed. Both are silent no-ops today, which means the UI has animating and non-animating entrances side by side.

The policy is deliberately conservative: motion may confirm an action or explain a spatial change, and nothing else. Infinite loops on content surfaces are removed. Everything that remains is gated.

Removed

  • All infinite float/float-slow/float-subtle/float-gentle loops on cards, badges, avatars.
  • Hover scale() + glow on content cards (transform on a reading surface causes reflow and vestibular load).
  • Broken classes: animate-fadeIn (43 uses, no keyframes) and animate-in … (missing dep) — one real fadeIn replaces both.
  • Any transition longer than 300ms.

Retained and gated

  • Enter/exit for modals, drawers, dropdowns (200–300ms, ease-out).
  • Hover/press feedback on buttons and rows (150ms, colour only).
  • Progress and skeleton shimmer — the only loops allowed, both with a static fallback.
  • One global block: @media (prefers-reduced-motion: reduce){ *{animation-duration:1ms!important;transition-duration:1ms!important} }

Every view designs four states

L5 requires empty, loading, error and partial-data states to be designed rather than blank or raw. Today there are zero skeletons and nine scattered animate-pulse.

Loading

Skeleton mirroring the final layout. Never a bare "Loading…" string, never an empty box. Announced with role="status".

Empty

EmptyState with title, one sentence of explanation, and the primary action that creates the first record.

Error

Plain-language message, a retry action, and the reference ID if one exists. Announced with role="alert". Never a raw stack or a red border alone.

Partial

Render what loaded, mark what didn't inline, and never block the whole page on one failed request.
