01 · Method

What was reviewed, and how

The workbench defines a seven-step flow: scope, set up, light pass, dark pass, functional walk, log, verdict. This report completes steps 1 and 6 only. Everything between them is runtime work that needs a browser, two themes, a keyboard and a screen reader — none of which a source review can substitute for. Reporting that honestly is the point: the workbench's first rule is that a blank is never a pass, and its second is that a pass is not a conformance claim.

Where a claim could be measured, it was measured. Every contrast figure in this report comes from running the WCAG relative-luminance formula over the hex values actually present in app/globals.css and components/DashboardPage.tsx, truncated to two decimals — never rounded, because 4.49:1 does not meet 4.5:1. Every count comes from a regex sweep over app/ and components/.

Done in this pass

Scope: gallotrack-next/app + gallotrack-next/components (54 .tsx, 14,078 lines). Review details, source-level structural and semantic checks, token-level contrast math, duplicate-pattern inventory, size-scale census.

Not done — blank

Light pass, dark pass, keyboard-only walk, screen reader pass, 200%/400% zoom, 320px reflow, text-spacing override, forced colours, reduced motion, real-device pass, browser matrix, automated axe scan, evidence screenshots.

Why the split matters

Eight of the nine checklist categories contain at least one unit that is only answerable by rendering the page. Those units stay blank regardless of how much source review is done — which is exactly why the suggested verdict is Incomplete rather than Reject.

Review details. App under review: GalloTrack Web (Next.js 16 / React 19 / Tailwind v4 / Supabase). Build: commit d147d46, branch ui-improvement. Standard: WCAG 2.2 A and AA, plus practice checks. Roles tested: none yet — owner and admin accounts still need a runtime walk. Devices and browsers: none yet. Reviewer: Syntaxure Labs. Review date: 2026-10-04.

The failures are concentrated in the light theme, with one dark-theme exception. Text contrast passes in dark because --muted-foreground was tuned to #94a3b8 against a near-black surface, while the light theme reuses raw palette utilities (slate-400, emerald-500, amber-500) that were never tuned for their background. The exception is the chart palette: it is hardcoded, so the same six-colour emerald ramp that fails three segments on white fails a different segment (#065f46, 2.32:1) on the dark card. This is checklist item M6 — brand and accent colours must be re-tuned per theme — and it is exactly what a token layer prevents: one value in one file instead of 80 literals across 39.

Not measured here: any colour sitting on a backdrop-blur layer, gradient, or image. The dashboard uses bg-card/85 backdrop-blur-md for the topbar and bg-card/95 for the mobile bar, so the rendered pixel differs from the CSS value. Those need the DevTools eyedropper during the light pass.

Why zero passes are recorded

Source review can prove a failure but rarely prove a pass. header/nav/main/aside exist, <html lang="en"> is set and all 19 images carry alt — but the workbench only accepts a pass for units sampled on every screen and state, and no screen has been rendered yet. Those units stay blank until PR 7.

What unblocks the verdict

Clear the 8 S2 findings (PRs 2–5), then run the runtime passes to fill the 71 blanks (PR 7). Only then can rule 6 return Approve. Until the S2s are cleared, the verdict sits at rule 2 and cannot climb.
